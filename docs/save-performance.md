# 保存与关闭性能分析

记录日期：2026-10-10。目标是在完整保存、完整读回和可恢复备份仍成立时，减少退出时
重复编码、等待和临时分配。原始诊断日志及本机状态不公开；本页给出汇总、方法和复现入口。

## 真实进程退出对照

以下是两个开发成品的配对结果，**不是公开 2.3.3 DMG 与本 PR 2.3.4 成品的直接对照**。
同一 arm64 Mac、macOS 27.2、固定 Temurin 21.0.12.1、512 MiB 堆、同一夹具字节码；
旧/新进程交替运行，每次独立 home/data/tmp。重笔迹夹具有 9600 个当前笔迹点、1201 个合法回放帧。

终点为另一个进程收到该测试 PID 的内核 `NOTE_EXIT` 通知；起点为实际窗口关闭进入
应用的 `CLOSE_START`。包含保存、界面完成回调和 JVM 退出，未覆盖物理鼠标的投递延迟。
跨进程时钟对齐约有 1 ms 量化，内核通知也受调度影响。

| 场景 | 有效配对数 | 旧成品中位数 ms | 新成品中位数 ms | 减少 |
| --- | ---: | ---: | ---: | ---: |
| 无笔迹，立即关闭 | 5 | 297.1 | 258.2 | 13.1% |
| 无笔迹，空闲后关闭 | 3 | 263.1 | 165.9 | 37.0% |
| 9600 点，立即关闭 | 3 | 951.8 | 520.5 | 45.3% |
| 9600 点，空闲后关闭 | 4 | 750.7 | 377.6 | 49.7% |
| 空闲保存后再编辑关闭 | 3 | 1089.3 | 356.4 | 67.3% |
| 确认设置后关闭 | 3 | 753.4 | 330.5 | 56.1% |
| 完成题目后关闭 | 3 | 964.7 | 539.8 | 44.0% |

每次退出后完整读回盘面、坐标 raw double bits、工具历史、存档点、设置、回放与用时。
失败、超时和读回不一致的运行不作为优化样本。旧基线的 20 层历史案例在 512 MiB 下
无法完成，因此不计算对照比例；不能称为“无限提升”。新成品独立压力样本各 3 次，
20 层立即/空闲中位数为 681.8/319.9 ms，100 层为 1305.7/357.4 ms。

对照成品还共享当时的其他 UI 改动，数字是组合结果，不能把全部差值归因于单个函数。

`dba9de0d81847ab3c35a4768f87dce5da65afba70c8865b845f58ecdcc7f1b10`；
优化开发成品：`2a03fedb3248e6a5f49b40e5d1a2606bc43e67a3f1386d408812d3abf5857122`。
这两个摘要标识采样对象，不能替代待发行版本的精确源码与成品映射。

## 为什么退出更快

1. **将完整会话保存提前到空闲时。** 至少静置 5 秒，捕获尝试间隔至少 30 秒；单个有界、
   低优先级工作线程写稳定快照。新文件仍完整解码验证，关闭时继续补存最后修改。
2. **合并设置写入。** 连续操作合并 1 秒、实际后台提交至少间隔 5 秒；明确确认或退出立即提交。
3. **识别真正未变的内容。** 内容相同且磁盘 SHA-256 与成功验证的字节一致才跳过编码与替换。
   同大小、同修改时间的损坏仍需发现；旧快照提交序号不能覆盖新状态。
4. **共享精确笔迹与紧凑数组。** 写时复制坐标与历史共享减少重复对象；保留精度和所有历史。
   本机工作会话 v2 使用带版本/类型/长度检查的二进制载荷，减少逐元素 XML 节点。
5. **缩短完成通知等待。** 有界保存线程直接向 EDT 投递完成通知，避开当时随包 JDK
   `SwingWorker.done()` 约 33 ms 的合并定时器。首次 paint 和真实 EDT 等待仍单独测量。

回放内容变化时仍整体写 `.hrep`，约 120 ms 合并请求不是增量日志。计时 heartbeat 用 checkpoint
记录；回放退出写入失败时，本机会话严格比较用时并提供恢复兜底。本 PR 又补上同帧数、
同身份及一致盘面的异常恢复检查，正常退出更快不能代替异常重启可靠性验证。

## UI 收益与仍有限制的部分

圈叉字形偏移缓存、精确坐标共享减少绘制与历史复制的重复工作；常态来源和真假语义
分开表达，S 共边、P 起点/选择轮廓与 L 字形进一步统一。布局变化不应让数字与标记中心偏移。
这些 UI 行为见 [2.3.4 说明](releases/2.3.4.md)，不能只靠保存基准宣称其手感改善。

三个交替 JVM 的微基准中，100 层历史复制从 12.147 ms/29.01 MiB 降至
0.749 ms/0.85 MiB；12 次整笔擦除从 134.648 ms/74.25 MiB 到 118.522 ms/47.31 MiB。
**12 次范围擦除为 144.826 → 148.139 ms，未证实提速**；小差异受方法与噪声影响。
分配量不是峰值内存，微基准也不是物理输入到可见画面的端到端时延。

密集画面仍观察到约 0.2 秒完成回调排队及数百毫秒界面延迟，轻量立即关闭收益较小。
未确认 Intel/M1、旧 macOS 或其它系统/负载下的相同比例。最新 UI 的深色重开真实窗口
与第二次原生 Quit 验收尚待完成；不将离屏 paint、Linux Swing 或旧成品读回当作该验收。

## 如何复核

源码回归运行 `script/check_cloud.py` 与 `test/telemetry`；测量入口为
`script/compare_save_lifecycle.py`、`script/collect_save_fixture.py` 和
`script/observe_save_exit.swift`。完整参数、起止定义、失败门禁及原生成品验证入口见
[采集说明](save-telemetry.md)。使用新输出目录和隔离数据，只观察自己新建的测试 PID。
保存日志默认只留本机，但目标文件路径可能含个人目录；分享诊断前仍须单独脱敏。
