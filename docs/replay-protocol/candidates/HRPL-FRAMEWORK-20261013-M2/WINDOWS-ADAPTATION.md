# Windows 集中适配任务

目标：在保持 Windows 原生功能、操作与普通录制性能的前提下，适配 `HRPL-FRAMEWORK-20261013-M2`，使两端能够正确读取和观看完整回放、原样保存，并从选定帧真实盘面开始独立解题。用户不再充当传话筒，两端 AI 直接使用 [PR #2](https://github.com/LoveMu-498/hodoku-macos/pull/2)。

先读取本包四份完整合同、manifest.json 和 Mac 实际应用结果。0.2 支持 16 MiB 的真实帧 phaseLabel；其他普通文本与整体文件容量不变。保留 v3/O11 和 0.1 读取能力。对新交流格式采用明确导出入口，沿用原生普通录制/保存行为。

按一个实施批次完成：

1. 将独立编解码器接入真实读取/导出路径；普通候选显示取 candidates，userCandidates 独立完整保存。原样保存保留源文件全部字节。未知可选数据按合同保留，重要数据不能显示时用完整预览或明确部分观看。
2. 接入通用五类图形、固定白底黑字等宽九宫格和候选 3x3 槽位；完整原生预览保持自身样式，以宽高比完整显示。完整 phaseLabel 单独可滚动，不因长说明裁掉内容。原生画面与通用画面分别实测两种大小及宿主主题。
3. 交流导出可从已经保存的原生帧/证据冻结画面和说明，禁止重新求解、补造原记录不存在的证据。未保存原录制主题的旧记录应如实说明；不要求为交流格式给所有普通录制新增截图开销。
4. 从帧进入棋盘只使用四组真实数组，归档源文件，新建身份，历史圈叉/证明/原生 opaque 数据保持不执行。已有其他原生载入入口可保留。若提供修改导出，落实源文件归档、新身份、旧绑定数据丢弃并记损失；失败保护上次成功文件。
5. 一次运行 MATRIX.md：Mac→Windows→Mac、Windows→Mac→Windows、完整原样回传、真实显示、长说明、修改/续解、v3/O11 和异常文件。返回完整结果、具体构建标识及合成回传文件。纯原型通过不能替代真实应用路径。

普通技术细节自行实现和修复，无需逐字段确认；已收到的需求一起处理。若协议仍卡住某项原生功能，集中说明实际功能、冲突规则、复現证据及可行的扩展/放宽方案。Mac 会先自身兼容或修改协议；只有确实要牺牲功能才请用户决定。不要以继续传样例代替完成应用适配。

维护者在本次共享任务中已明确要求“先把 Mac 端完整适配并验证好，再通过 PR 让 Windows 集中适配”，并要求普通技术细节自行处理、仅牺牲功能时确认。本次交接因此要求真实应用适配，取代此前仅准备原型的交接范围。Windows 仍遵守自身工具权限和直接用户约束；如存在不能由这条维护者交接解除的本地限制，集中报告具体来源与阻点，继续不受限工作。

回传一次包含：候选包与四合同哈希、实际接入版本、逐项 PASS/FAIL/NOT_RUN、回传 fixture 与哈希、全部剩余具体冲突。确认与验证附在同一结果中，收件、哈希和普通修复不各开一轮等待。
