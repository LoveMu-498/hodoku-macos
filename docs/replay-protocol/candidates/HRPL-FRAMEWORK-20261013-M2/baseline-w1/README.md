# W1 candidate package

This is a complete optional unified-frame candidate, not a shipped application format or bilateral agreement. Read SPEC.md, CONVERGENCE.md, INITIATIVE.md and FRAMEWORK.md against manifest.json. All four contract hashes are part of confirmation. MATRIX.md distinguishes prototype results, current application results and Mac results.

Pure synthetic binary fixtures and expected.json are under fixtures/. Run Python 3 with the standard library:

```text
python replay_framework_candidate.py verify fixtures
```

To regenerate only the framework test corpus:

```text
python replay_framework_candidate.py generate fixtures
python replay_framework_candidate.py verify fixtures
```

mac-o11-hmx5.hrep and windows-o11-return.hrep are the previously public synthetic v3 compatibility exchange and are separate from the generated v4 corpus. The 1x1 preview fixture tests the PNG carrier only; it does not prove fidelity of the frame screenshot. Never count it as complete visual acceptance.

The candidate uses explicit micro-board geometry and recorded styles, without a solver. The isolated O11 projection entry point requires captured style/result input; its synthetic tests are preparation, not an implemented Windows recorder. Old Windows readers reject v4, so neither product may silently enable v4 export before its reader is deployed. Original v3 and O11 compatibility is retained.

Windows technical decision: AMEND by adding this optional profile and updating the new-framework convergence scope. Windows accepts the exact four contract hashes in manifest.json within the current proposal/prototype authorization; no acceptance of different future bytes is implied. Mac must independently review this same candidate or deliver a complete amendment. Application recording/editor/continuation integration, deployment, merge and synchronization remain separately authorized and tested.
