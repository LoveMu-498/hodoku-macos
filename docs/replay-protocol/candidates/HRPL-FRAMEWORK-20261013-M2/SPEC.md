## 功能保持与两项基础能力

用户 2026-10-05 明确核心目标为“能够看回放，并从该帧进入棋盘”。协议不得作为原生功能的上限：不能为了旧接收端而删减技巧、改变推理结论、降低圈叉／候选标记的表达、改变用户操作或漏记重要历史证据。产品功能按其原生合同实现，协议不足时改记录／转换适配层或扩展协议。

| 能力 | 共同要求 | 不要求两端相同的内容 |
| --- | --- | --- |
| 看回放 | 显示当时棋盘、重要圈叉／候选高亮／线／文字及阶段；未理解技巧仍能忠实显示 | 求解器、技巧枚举、内部证明对象与本端快捷键 |
| 进入棋盘 | 用选定帧真实数值、给定数、候选创建独立解题分支 | 重新执行历史技巧、复现另一端的预览交互、让所有历史标记继续可编辑 |

进入棋盘不是读取一张效果图猜出盘面，也不是把红色历史删除重新加入候选。历史展示层与可编辑状态分开；只有明确可编辑的已知原始标注可以按本端已有规则恢复。未知扩展留作只读来源，不自动成为执行依据。

## 面向未来功能的记录方式

记录分为三个相互独立的部分：真实棋盘快照、冻结显示证据、可选原生语义。原生数据保留完整；记录器／导出适配器将其投影为观看材料，不能反向修改原生功能来满足投影。

冻结显示证据应逐步采用通用、非执行的表达：格／候选或声明坐标系的锚点、颜色与宽度、文本、线／箭头、圈／叉、区域等。不需要接收端先认识 Finned Swordfish 或 CELL_FORCING 才能显示其图形。新技巧若能用已支持的通用显示表达，不需为技巧名称升级共同协议。超出通用表达的效果可提供固定预览图作为观看后备，棋盘仍用独立快照进入。

这里确立显示模型的扩展方向，不冒称现有 v3 已有统一图形或图像载体。新增具体编码、媒体引用与版本先做有边界的扩展提案；不执行脚本、不依赖外部地址取资源。新载体准备期间保留完整原生记录，并真实声明接收端的显示能力。

未来可选扩展使用明确命名空间／版本／长度或等效可跳过边界，接收端不懂其内部算法也可保留原文或字节，读取棋盘及支持的显示后备。当前 HMX／O 等旧编码的限制不因这项设计目标自动消失，能力表必须反映事实。

只有改变共同核心、既有标签含义、通用显示表达或新增共同能力时，才需共同修订。在已约定的可选原生扩展范围内增加功能及内部版本，可以由该端独立演进，并维护本端记录／回归；不得因此阻止本端功能开发或要求另一端采用同一算法。

## 三层边界

| 层 | 管什么 | 演进边界 |
| --- | --- | --- |
| 共同容器 | 字段顺序、编码、帧、盘面、时间 | 破坏布局或安全读取时升级容器主版本 |

| 平台扩展 | 本端完整证明、恢复、精确涂鸦等 | 平台独立版本；不能改写共同核心，丢失必须声明 |

应用版本、容器版本、协议修订号、平台扩展版本分别记录。候选规范编号不写入现有 hrep，不声称当前读取器具备能力协商；文件内能力声明的载体须作为独立提案通过后才能启用。

## 已核实共同容器基线

两端被检查的源码使用 HRPL `0x4852504C`，版本 3。大端 Java DataOutputStream；UTF 是 modified UTF-8，按编码字节限制到 65535，不是通用 UTF-8 文件。

依次：magic:int、version:int、id:UTF、startedAt/elapsedMillis/endedAt:long、completed:boolean、frameCount:int。

每帧依次：operationId/wallTimeMillis/elapsedMillis:long、label:UTF、overlayData:UTF、methodStep:boolean；然后 81 格各 value:byte、fixed:boolean、candidates:short、userCandidates:short。行列位置用格索引 0..80，候选 atom=cell*10+digit，digit=1..9。

盘面 value 为 0..9，0 表示空；fixed=true 的格不能为空。两个候选 short 只用低 9 位，数字 d 对应 bit(d-1)；已填格的普通 candidates 为 0。初版共享写出采用当前 Mac 已实施的保守容量档案：文件不超过 128 MiB、1..100000 帧、UTF 每项编码不超过 65535 字节；operationId 和有效 elapsedMillis 不递减。新的更大档案先提案，不静默截断。源代码是否已落实这些限额在能力表分别声明。

现有 Mac 明确只接本格式族 v3，不支持已退役的旧 Mac 外壳。版本支持范围必须逐项列出；不能用版本整数大小替代格式定义。Mac 私有尾扩展及完整字段见 ../replay-file-format.md；本候选规范不要求 Windows 执行私有证明。

## 共同语义候选要求

- 盘面是当时真实状态；历史已删候选可以只读高亮，不能恢复为盘面候选。原始输入、证据展示、应用后盘面要区分，不能凭颜色把历史步骤变成可执行对象。
- 时间区分真实记录时刻、有效解题用时、播放器停留时长。事件顺序与操作组身份保留；不得在导入时补造不存在的初始状态或操作。
- 格／候选位置用语义锚点；自由几何坐标必须声明像素或归一化、参照空间和大小。RGB/ARGB 是外观，色组身份与圈真／叉假、起点、待接纳结论分别表达。
- 单色多个起点是至少一个为真还是每个均真，必须明确。多分支共同结果必须保存覆盖前提、结果真／假方向与来源；中间推导是否机器验证另外标记。MT 开关不能替代这些证据。
- 应保存用于历史展示的冻结结论，不以新版本求解器在观看时重算后覆盖历史。允许独立验证或补充说明，须明确区分。

## 兼容能力分别声明

每端能力档案填写固定源码版本、协议基线和每项能力：读取、正确展示、另存保留、编辑后保留、从帧开始解题。只支持读取不能标记完整兼容。

未知的可选标签保留原始行和顺序，不执行；已知标签损坏严格处理，不能伪装成未知。无能力显示时说明未显示，不能反转真／假含义。重要画面缺失时只能声明部分观看，不能用“能打开”通过完整观看验收。默认完整交换不静默丢原生扩展；现有写者不能保留时如实声明，使用明确有损的旧版导出或保留原始文件，不能削弱本端功能。

必须理解的重要新语义，不能仅在 v3 中新增一个旧端会忽略的 required 标记来保证安全；旧客户端不会因此自动拒绝。需要通过已升级读取器的受控过渡、新容器版本，或明确有损的兼容导出保护。

读取边界的最低合成样例见 fixtures/README.md；扩展提案另覆盖非法格／数字、非有限几何值、错误帧顺序、未知必要版本、UTF 溢出、截断与过大文件。不能静默截断或覆盖上次成功文件。
