# M2 unified-frame adaptation package

Package ID: `HRPL-FRAMEWORK-20261013-M2`. Complete Mac amendment and implemented Mac adaptation based on the received Windows W1 requirements. The candidate contracts are SPEC.md, CONVERGENCE.md, INITIATIVE.md and FRAMEWORK.md. Confirm their exact hashes in manifest.json. Mac application paths and native Swing windows have been verified as described in [results/mac-application.md](results/mac-application.md). Windows M2 application adaptation and the subsequent real application round trips remain `NOT_RUN`; an old W1 acceptance does not accept M2.

This package defines profile `HRPL-FRAME/0.2` inside explicit HRPL v4. The four board arrays, existing five primitives, native/preview bindings, limits, source archival and no-history-execution rules are retained. The exact frame phaseLabel permits 16 MiB UTF-8, while every other ordinary text remains limited to 65535 bytes. Shared canvas/candidate placement, standalone preview, complete scrollable explanation, and export-time freezing of saved native evidence are explicit. No new schema fields are introduced. Ordinary native recording retains its existing path; PNG capture runs only on explicit cross-platform export. This is confirmed by code inspection and replay regressions, not a recording-performance benchmark.

`baseline-w1/` contains the exact historical W1 contracts/manifest/readme/matrix. `fixtures/` preserves all original W1 fixture bytes and expected.json, including the historical results.json. Do not interpret that historical results file as a new application run. A 1x1 preview tests PNG transport only.

Use Python 3 standard library; no installation or application source is required:

```text
python replay_framework_candidate.py verify fixtures --report results/local-w1.json
python replay_framework_candidate.py self-test fixtures --report results/local-m2.json
python replay_framework_candidate.py verify-file mac-fixtures/java-codec-long-label.hrep
```

The first command checks the unchanged 18 W1 cases plus canonical bytes, unmodified saves and isolated edit/continuation preparation. The second checks ten M2 long-label and known-record-only exemption cases. The last reads the independently Java-generated 0.2 long-label file and checks canonical semantic and unchanged-byte preservation. These are codec results, not application or GUI acceptance.

The Mac validation environment was macOS 27.2 arm64 and Temurin 21.0.12.1, compiling all source and test files with `--release 8`. The independent Java codec passed 111 checks, the renderer 132, native capture 46 headless / 49 GUI, and application integration 46 headless / 54 GUI. Legacy v3/O11, replay core, long-text persistence, branch and authored-evidence regressions also passed. GUI counts include the common checks and must not be added to their headless counts as independent coverage. See [MATRIX.md](MATRIX.md) for the acceptance boundaries.

`mac-fixtures/` contains synthetic files produced or saved through the real Mac application paths: `mac-native-proof-frames.hrep`, its exact unchanged return `mac-native-return.hrep`, `mac-modified.hrep`, `mac-long-description.hrep`, `mac-w1-unchanged.hrep`, `mac-noncanonical.hrep`, and the legacy native source `native-proof.hrep`. `java-codec-long-label.hrep` remains a codec-only fixture. The W1 source fixtures were generated by the Windows prototype; importing them in the Mac application does not establish a Windows application export.

`evidence/` includes rendered captures of the two displayed Swing windows, plus pure-board images for 480/810 sizes and LIGHT/DARK host themes. The separate capture probe also used Robot to check a displayed native window. These checks do not claim physical mouse interaction or acceptance of an installed, packaged application. `reference-java/` carries the four new helpers and four probes; `source-hashes.json` identifies the exact related Mac sources used for validation.

The modified-export API was exercised for metadata changes, new identities, source archival and explicit loss of stale native data. It rejects changes to the board or phaseLabel of an unknown important full-image frame rather than rebinding obsolete pixels to changed content. Read-only viewing, exact direct saving and independent continuation from the four board arrays remain available.

Windows work is [WINDOWS-ADAPTATION.md](WINDOWS-ADAPTATION.md): adapt the real application in one batch, preserve native functionality, return direct-save files and actual display evidence, and report concrete conflicts together in the shared PR. The two agents use that PR directly; the user need not relay output. Ordinary implementation details do not need separate discussion rounds. Only a concrete remaining conflict requiring loss of native functionality is escalated for the user's decision.

When package artifacts change, run `python refresh_manifest.py` to regenerate the complete hash manifest. This intentionally changes package evidence hashes without changing contract hashes unless those files were edited. Publication, merge and release are separate actions. The PR is a shared working channel; publishing a comment does not wake an idle Windows agent or establish a background listener.
