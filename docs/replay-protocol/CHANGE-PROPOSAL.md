# 共同协议修订提案模板

- 提案编号：
- 提出端与固定源码版本：
- 基线协议 ID / commit（若已发布）/ SPEC.md SHA-256：
- 类型：纯流程演练／兼容新增／语义变更／布局变更／勘误：
- 传递渠道：GitHub PR URL／离线包编号：

## 原因与前后定义

写出原定义、新定义、精确字段和真／假等含义。附 changes.patch 或明确前／后文本。不将运行日志、私人回放、路径、账号或凭据放入公开提案。

## 兼容与迁移

旧 Mac、旧 Windows 各会怎样读取、显示、另存和编辑？哪些必须拒绝、允许降级或丢失？新读取能力何时上线，新写出何时启用？

## 样例与验收

合成正常／失败文件、预期语义、双向往返结果、实际渲染、允许损失清单；说明未验证项目。

## 审阅与确认

Mac：待确认。Windows：待确认。审阅结论：待确认。

接收确认编号／基线哈希／修改后哈希／最终协议版本：待填写。提交成功、收到确认、双方能力实现分别记录。

## AI 直接收敛

遵循 CONVERGENCE.md。提交人一次性给 ACK／完整 AMEND／BLOCK，不仅给建议。反提案应包含准确候选 SPEC 哈希、明确接受范围、维护团队的委托与真实证据。双方有权接受同一候选即可在确认记录冻结，不把合并或全部可选功能实现混为同一门槛。普通技术修订由获授权 AI 在共享入口完成；真实阻碍一次性交开发团队，不循环转述。
