# Replay interchange

The `.hrep` binary format is a self-contained replay, not Java serialization or XML beans. The current writer emits envelope version 4 (big-endian numeric fields, Java modified UTF for bounded text), and the reader accepts envelope versions 1–4. The envelope contains attempt ID, wall-clock labels, effective elapsed time, terminal state, ordered complete operation groups, every immutable board, typed proof bytes and savepoint markers. Versions 1 and 2 precede savepoint markers; version 1 also lacks end time. Version 4 adds the source replay/frame identity and independent initial box/chain geometry for a new attempt started from a replay frame. This geometry contains no executable historical proof and never requires the source file. Native proof and authored proof envelopes each have their own version 1 discriminator. No solver execution or external path lookup is required to display a replay.

The external interchange boundary additionally validates known event kinds, initial frame, grouped native proof/application pairs (including several pairs in one batch), authored input/result/application triples, matching pre-application boards and authored evidence, fixed puzzle identity, elapsed bounds, and savepoint indices. Incorrect historical values or deletions are preserved. A claimed completed replay must end at a correct complete board. Effective elapsed timestamps must be nondecreasing across the entire recording; equal-time frames retain their stored order. Wall-clock labels need not be increasing because the system date can change.

An active export takes a complete-prefix snapshot on the EDT before encoding, leaves the original attempt open, and clears local pin/retention flags. Only a generic interruption marker is exported; detailed recovery errors, paths and diagnostic logs are excluded. User-entered savepoint names are part of the intended recording. Import is read-only, does not populate retention, and does not change current attempt identity or live board. Export cannot target app-managed replay storage.

Envelope limits: 128 MiB file, 100,000 frames, 4 MiB evidence per frame, 10,000 savepoint markers; proof codecs add collection and index bounds. Unknown versions, unexplained frame kinds, incomplete groups, invalid payloads and trailing data fail explicitly. A file-extension match alone never makes a file trusted.
